# /bpd:start — начать проект

Самый важный момент во всём фреймворке. Чем лучше поймём проект сейчас, тем
качественнее будут все этапы: план этапа опирается на `PROJECT.md`, а не на память
разговора, которого через неделю не будет.

## Что прочитать перед работой

1. `${CLAUDE_PLUGIN_ROOT}/references/rules.md` — общие правила: дома фактов,
   нумерация, значения в config.json.
2. Шаблоны из `${CLAUDE_PLUGIN_ROOT}/templates/`: `PROJECT.md`, `ROADMAP.md`,
   `STATE.md`, `CLAUDE.md`, `config.json`.

## Шаг 1. Проверить, что место свободно

Есть ли `.bpd/` в текущей папке?

- **Есть** → сказать: «В этой папке уже есть проект BPD. Посмотреть прогресс —
  `/bpd:status`, изменить карту — `/bpd:update`.» Остановиться.
- **Нет** → продолжать.

## Шаг 2. Интервью

Открыть разговор обычным текстом, **не** через AskUserQuestion:

> «Расскажите, что за проект вы хотите сделать? Опишите свободно — что это,
> для кого, какой результат хотите получить.»

Дождаться ответа. Дальше задать 2–4 уточняющих вопроса — текстом или через
AskUserQuestion, как удобнее по ситуации. Обязательные темы:

- **Конечный результат.** Что будет лежать на столе, когда всё готово?
- **Для кого.** Аудитория, заказчик, для себя.
- **Ограничения.** Сроки, бюджет, инструменты, объём, чего делать нельзя.
- **Опыт.** Делал ли человек подобное раньше — от этого зависит размер шага.

Если ответ уже прозвучал в свободном рассказе — не переспрашивать. Следовать
за содержанием, а не за списком.

AskUserQuestion:

```
AskUserQuestion:

    - label: "Автоматический"                 description: "Делать самому, показывать результат в конце"
```

## Шаг 5. Проектные фичи

Перечитать всё, что человек рассказал в интервью. Если он упоминал особые
требования, идущие рядом с основной работой, — записать их как фичи.

Примеры:

- **Лог или черновик** по ходу проекта — для обучения, документации, отчёта.
- **Сбор данных** — метрики, статистика, список ошибок.
- **Параллельный артефакт** — что-то, что рождается вместе с основным результатом.

Для каждой фичи проговорить: как работает, какие файлы создаёт, когда обновляется,
по какому признаку отбирается информация. Фичи поедут в `config.json` на шаге 6.

Если ничего такого не звучало — фич нет, и выдумывать их не надо.

## Шаг 6. Создать config.json

Значения — машинные, английские. Правила и таблица перевода — в `rules.md` § 7.

```json
{
  "project_name": "название из интервью",
  "scale": "fast | medium | large",
  "mode": "interactive | automatic",
  "use_subagents": {"plan": false, "do": false, "check": true},
  "features": {},
  "created": "ГГГГ-ММ-ДД",
  "bpd_version": "2.2.0"
}
```

`use_subagents` — это три отдельных флажка, по одному на роль. Таблица умолчаний
и обе законные формы записи — в `rules.md` § 7. Коротко: `fast` → `false`,
`medium` → проверка в свежем контексте, план и работа в текущем чате,
`large` → все три роли в свежем контексте.

При `mode: interactive` не включать роль `do` без просьбы человека: субагент
его не видит и подтверждений не спросит.

Пример заполненных фич:

```json
"features": {
  "edu_log": {
    "enabled": true,
    "file": ".bpd/EDU_LOG.md",
    "description": "Лог для образовательного материала",
    "filter": "Записывать только то, что поможет другому человеку повторить результат"
  }
}
```

Дату брать реальную сегодняшнюю (`date +%Y-%m-%d`), не выдумывать.

## Шаг 7. Создать PROJECT.md

По шаблону `${CLAUDE_PLUGIN_ROOT}/templates/PROJECT.md`. Заполнить всё, что узнали
в интервью. **Не сжимать** — это главный документ проекта, его будут читать
планировщики всех этапов, когда разговора уже не будет.

`PROJECT.md` живёт дольше всех: он не перезаписывается, а дописывается. По ходу
проекта сюда добавляются решения с обоснованием. См. `rules.md` § 5.

## Шаг 8. Создать ROADMAP.md

Разбить проект на этапы. Сколько — по масштабу: `fast` 1–4, `medium` 5–14,
`large` 15 и больше.

Для каждого этапа:

- **Название** — короткое и понятное.
- **Описание** — одно предложение.
- **Цель** — что этот этап даёт проекту.
- **Зависит от** — какие этапы должны быть готовы раньше.
- **Критерии готовности** — 2–5 проверяемых пунктов.

Создать по шаблону `${CLAUDE_PLUGIN_ROOT}/templates/ROADMAP.md`.

**Статусов в карте нет** — они вычисляются по файлам (`rules.md` § 3).
Номера выдаются один раз и потом не меняются (`rules.md` § 6).

Показать карту пользователю. В режиме `interactive` спросить:

```
AskUserQuestion:
  header: "Дорожная карта"
  question: "Вот дорожная карта проекта. Всё верно?"
  options:
    - label: "Да, всё верно"          description: "Сохранить и продолжить"
    - label: "Нет, нужны изменения"   description: "Хочу что-то поменять"
```

Если «Нет» — спросить что, поправить, показать снова. Повторять до согласия.

## Шаг 9. Создать STATE.md

По шаблону `${CLAUDE_PLUGIN_ROOT}/templates/STATE.md`.

В `STATE.md` **нет** ни статусов этапов, ни процента прогресса — они считаются
на лету при показе. Там живут: история действий, проблемы, на чём остановились,
следующий шаг.

## Шаг 10. Создать папки этапов

Для каждого этапа из карты:

```bash
mkdir -p .bpd/stages/01-korotkoe-imya
```

Имя — номер с ведущим нулём, дефис, короткое имя **латиницей** в нижнем регистре,
без пробелов (транслит русского названия). Имя создаётся один раз и не меняется.

## Шаг 11. Создать CLAUDE.md

По шаблону `${CLAUDE_PLUGIN_ROOT}/templates/CLAUDE.md`, в корне проекта.
Если `CLAUDE.md` уже есть — **не затирать**, а дописать в него раздел про BPD.

Это единственный надёжный способ передать контекст будущим сессиям: `CLAUDE.md`
из корня проекта читается автоматически при каждом запуске. Поэтому сюда идёт
то, что должно доехать до следующей сессии: о чём проект, какие технологии,
какие правила работы, где лежит память проекта.

BPD **не** пишет ничего в память Claude Code за пределами проекта. Весь контекст
живёт в папке проекта — его видно, его можно поправить руками, он переезжает
вместе с проектом.

## Шаг 12. Самопроверка

Пройти по чеклисту ниже. Если пункт не закрыт — **закрыть сейчас**, а не показывать
сводку с дырой.

- [ ] Интервью проведено, проект понятен
- [ ] Масштаб и режим выбраны, записаны машинными значениями
- [ ] Проектные фичи зафиксированы (или честно записано, что их нет)
- [ ] `.bpd/` создана: `PROJECT.md`, `ROADMAP.md`, `STATE.md`, `config.json`
- [ ] В `ROADMAP.md` все этапы с целями и критериями готовности
- [ ] В `ROADMAP.md` нет колонки «Статус»
- [ ] Пользователь подтвердил карту (в режиме `interactive`)
- [ ] Папки этапов созданы, имена латиницей
- [ ] `CLAUDE.md` создан или дополнен, старое содержимое не затёрто
