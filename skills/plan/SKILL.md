# /bpd:plan — спланировать этап

## Что прочитать перед работой

1. `${CLAUDE_PLUGIN_ROOT}/references/rules.md` — правила статусов, поиска папки
   этапа, нумерации и работы с субагентами.
2. `${CLAUDE_PLUGIN_ROOT}/templates/PLAN.md` — шаблон плана.

## Шаг 1. Найти этап

Номер этапа передан в `$ARGUMENTS` (может быть пустым).

- **Номер есть** → работаем с ним.
- **Номера нет** → пройти по `ROADMAP.md` сверху вниз, вычислить статус каждого
  этапа по `rules.md` § 3 и взять **первый со статусом «Не начат»** (○).
  Отменённые этапы пропускать.
- **Все спланированы** → сказать: «Все этапы уже спланированы. Выполнить —
  `/bpd:do`.» Остановиться.

Найти папку этапа глобом по номеру: `.bpd/stages/NN-*` (`rules.md` § 2).
Папки нет — сказать об этом и остановиться, ничего не создавая.

**Если `PLAN.md` уже есть** — это перепланирование. Предупредить:
«У этапа N уже есть план. Перепланировать? Старый `PLAN.md` будет перезаписан.»
Если в папке есть `RESULT.md` — сказать и это: этап уже выполнялся.

## Шаг 2. Прочитать контекст

Обязательно:

- `.bpd/PROJECT.md` — цель проекта, рамки, **принятые решения с обоснованием**;
- `.bpd/ROADMAP.md` — описание этапа, зависимости, критерии готовности;
- `.bpd/STATE.md` — история, проблемы, на чём остановились;
- `.bpd/config.json` — `mode` и `use_subagents`.

Если этап не первый — прочитать `RESULT.md` предыдущих этапов. Не все подряд:
те, от которых этот этап зависит по карте, плюс последний по порядку.

## Шаг 3. Составить план

### Если `use_subagents: false`

В режиме `interactive` — задать 1–2 уточняющих вопроса по этапу. В режиме
`automatic` — не спрашивать. Дальше составить план самому, здесь же.

### Если `use_subagents: true`

В режиме `interactive` — **сначала** задать 1–2 уточняющих вопроса по этапу
(особые пожелания, приоритеты) и положить ответы в промпт субагента. Планировщик
пользователя не видит и спросить сам не сможет.

Затем запустить планировщика в свежем контексте. **Все пути в промпте — настоящие
и абсолютные**: субагент стартует с пустой головой и ничего из этой сессии не видит
(`rules.md` § 8).

```
Task(
  subagent_type: "bpd:planner",
  description: "Планирование этапа N",
  prompt: """
  Спланируй этап проекта BPD.

  Этап: N — [Название из ROADMAP.md]
  Папка этапа: [абсолютный путь к .bpd/stages/NN-imya]
  Пожелания пользователя к этому этапу: [ответы из вопросов выше, или «нет»]

  Прочитай в таком порядке:
  1. ${CLAUDE_PLUGIN_ROOT}/references/rules.md    — общие правила BPD
  2. ${CLAUDE_PLUGIN_ROOT}/templates/PLAN.md      — шаблон, по которому писать
  3. [путь]/.bpd/PROJECT.md                       — цель, рамки, решения
  4. [путь]/.bpd/ROADMAP.md                       — описание и критерии этапа
  5. [путь]/.bpd/STATE.md                         — история и проблемы
  6. [пути к RESULT.md этапов, от которых этот зависит]

  Создай [папка этапа]/PLAN.md по шаблону.
  """
)
```

Когда субагент вернулся — **прочитать созданный `PLAN.md` самому**. Если файла
нет или он не по шаблону, сказать об этом прямо и не притворяться, что этап
спланирован.

## Шаг 4. Каким должен быть план

Задачи — 3–10 штук на этап. Каждая:

- **конкретная** — не «поработать над текстом», а «написать введение к главе 3»;
- **проверяемая** — можно чётко сказать: сделано или нет;
- **атомарная** — одно действие, не «написать и отредактировать».

Чеклист качества — 3–5 пунктов. По нему потом пройдёт `/bpd:check`, поэтому
пункты должны быть такими, чтобы их мог проверить человек, не видевший работы.

Чеклист пишется **нумерованным списком без квадратных скобок**. Боксы `[ ]`
в `PLAN.md` есть только у задач: по ним считается готовность этапа, и лишние
галочки этот счёт ломают (`rules.md` § 3).

## Шаг 5. Показать план

Показать пользователю. В режиме `interactive` спросить:

```
AskUserQuestion:
  header: "План этапа"
  question: "Вот план этапа. Всё верно?"
  options:
    - label: "Да, начинаем"   description: "План утверждён"
    - label: "Нужны правки"   description: "Хочу что-то изменить"
```

Если «Нужны правки» — спросить что, обновить `PLAN.md`, показать снова.

В режиме `automatic` — показать и идти дальше.

## Шаг 6. Обновить STATE.md

Дописать в историю: дата + «Спланирован этап N». Обновить «Следующий шаг»
на `/bpd:do`. Статус и процент в `STATE.md` **не записывать** — они считаются
по файлам (`rules.md` §§ 3–4).

## Самопроверка

- [ ] Этап найден глобом по номеру, папка существует
- [ ] Контекст прочитан: PROJECT, ROADMAP, STATE, нужные RESULT
- [ ] `PLAN.md` существует на диске и открыт глазами
- [ ] Задачи конкретные, проверяемые, атомарные
- [ ] Чеклист качества из 3–5 пунктов есть
- [ ] Пользователь подтвердил план (в режиме `interactive`)
- [ ] `STATE.md` дополнен, статусы в него не записаны
