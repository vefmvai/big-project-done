<purpose>
Выполнить задачи этапа. Самый важный workflow — здесь происходит реальная работа.
Для больших проектов используются субагенты (свежий контекст на каждый этап).
</purpose>

<required_reading>
@./.claude/bpd/templates/RESULT.md
</required_reading>

<process>

## 1. Определить этап

**Если передан номер** ($ARGUMENTS): использовать его.

**Если номер не передан:** прочитать `.bpd/STATE.md`, найти следующий спланированный (статус "Спланирован") этап.

**Если нет спланированных этапов:** сообщить "Нет спланированных этапов. Используйте `/bpd:plan` чтобы спланировать следующий."

## 2. Прочитать контекст

Обязательно:
- `.bpd/stages/NN-название/PLAN.md` — список задач
- `.bpd/STATE.md` — текущие решения, проблемы
- `.bpd/PROJECT.md` — цель проекта
- `.bpd/config.json` — масштаб, режим, субагенты

Если это не первый этап — прочитать RESULT.md предыдущих этапов для контекста.

## 3. Обновить STATE.md

Перед началом работы обновить:
- Статус: "В работе"
- Последнее действие: дата + "Начато выполнение этапа N"

## 4. Выполнение задач

### Масштаб "быстрый"

Выполнить все задачи последовательно в текущем контексте.
После каждой задачи — отметить `[x]` в PLAN.md.

### Масштаб "средний"

Выполнить задачи в текущем контексте.
После каждой задачи:
- Отметить `[x]` в PLAN.md
- Записать результат в RESULT.md (обновлять по мере выполнения)

В интерактивном режиме — после каждой задачи показать прогресс: "Задача N из M выполнена. Продолжаем?"

### Масштаб "большой"

Запустить субагент `bpd-executor` через Task tool:

```
Task(
  prompt="Выполни задачи этапа.

<files_to_read>
- .bpd/stages/NN-название/PLAN.md
- .bpd/STATE.md
- .bpd/PROJECT.md
</files_to_read>

Инструкции:
1. Прочитай PLAN.md — там список задач
2. Выполни каждую задачу по порядку
3. После каждой задачи отметь [x] в PLAN.md
4. Когда всё выполнено — создай RESULT.md по шаблону из .claude/bpd/templates/RESULT.md
5. В RESULT.md запиши что сделано, какие файлы созданы/изменены, отклонения, проблемы

Работай автономно. Не задавай вопросов. Если возникла проблема — запиши её в RESULT.md и продолжай следующую задачу.",
  subagent_type="bpd-executor",
  description="Выполнение этапа [N]: [Название]"
)
```

После возврата субагента — прочитать созданный RESULT.md.

## 5. Создать/обновить RESULT.md

Если RESULT.md ещё не создан (быстрый/средний масштаб) — создать по шаблону:
- Что сделано (список выполненных задач)
- Созданные/изменённые файлы
- Отклонения от плана
- Проблемы
- Заметки для следующих этапов

## 6. Обновить STATE.md

Обновить:
- Статус: "Выполнен"
- Прогресс: пересчитать процент (выполненные / все этапы)
- Последнее действие: дата + "Выполнен этап N"
- Принятые решения: добавить если были
- Проблемы: добавить если возникли
- История действий: добавить запись

## 7. Показать итог

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 BPD ► ЭТАП ВЫПОЛНЕН
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Этап [N]: [Название]
Задач выполнено: [X] из [Y]
Отклонения: [Нет / Да — краткое описание]
Проблемы: [Нет / Да — краткое описание]
```

Для быстрого масштаба: "▶ Следующий шаг: /bpd:plan — спланировать следующий этап"
Для среднего/большого: "▶ Следующий шаг: /bpd:check — проверить результат"

</process>

<handling_problems>
## Если что-то пошло не так

**Задача невыполнима:** Пометить задачу как проблемную в PLAN.md (добавить `⚠️`), записать причину в RESULT.md, продолжить следующую задачу.

**Нужно решение пользователя:** Остановиться, показать ситуацию, спросить решение через AskUserQuestion. Записать решение в STATE.md (принятые решения).

**Нужно изменить план:** Если в процессе выполнения стало понятно что план неполный или неправильный — остановиться, предложить `/bpd:update` для изменения дорожной карты или вернуться к `/bpd:plan N` для перепланирования.
</handling_problems>

- [ ] Все задачи выполнены (или помечены как проблемные с объяснением)
- [ ] PLAN.md обновлён (чеклист задач)
- [ ] RESULT.md создан с полной информацией
- [ ] STATE.md обновлён (статус, прогресс, решения, проблемы)
</success_criteria>
