<purpose>
Проверить результат этапа. Автоматическая проверка + ручная проверка пользователем.
Для больших проектов — субагент-проверщик в свежем контексте (непредвзятая оценка).
</purpose>

<required_reading>
Шаблон CHECK.md уже загружен через execution_context команды.
</required_reading>

<process>

## 1. Определить этап

**Если передан номер** ($ARGUMENTS): использовать его.

**Если номер не передан:** найти последний выполненный, но не проверенный этап (статус "Выполнен" без CHECK.md).

**Если нет этапов для проверки:** сообщить "Нет выполненных этапов для проверки."

## 2. Прочитать контекст

Обязательно:
- `.bpd/stages/NN-название/PLAN.md` — задачи и чеклист качества
- `.bpd/stages/NN-название/RESULT.md` — что было сделано
- `.bpd/ROADMAP.md` — критерии готовности этапа
- `.bpd/config.json` — масштаб

## 3. Автоматическая проверка

Проверить:

**Все задачи выполнены?**
- Прочитать PLAN.md, посчитать `[x]` vs `[ ]`
- Если есть невыполненные — отметить

**Файлы существуют?**
- Из RESULT.md извлечь список файлов
- Проверить существование каждого через Glob/Bash

**Результат соответствует цели?**
- Сравнить цель из PLAN.md с тем что написано в RESULT.md
- Оценить: достигнута ли цель этапа?

**Критерии готовности из ROADMAP.md:**
- Проверить каждый критерий

### Для больших проектов — субагент

Запустить `bpd-checker`:

```
Task(
  prompt="Проверь результат этапа.

<files_to_read>
- .bpd/stages/NN-название/PLAN.md
- .bpd/stages/NN-название/RESULT.md
- .bpd/ROADMAP.md
</files_to_read>

Инструкции:
1. Прочитай PLAN.md — там задачи и чеклист качества
2. Прочитай RESULT.md — там что было сделано
3. Проверь: все задачи выполнены? файлы существуют? результат соответствует цели?
4. НЕ доверяй тому что написано в RESULT.md — проверяй реальные файлы
5. Создай CHECK.md по шаблону (он уже загружен в контексте)
6. Итог: Принято / Доработать",
  subagent_type="bpd-checker",
  description="Проверка этапа [N]"
)
```

## 4. Ручная проверка

Показать пользователю чеклист качества из PLAN.md:

```
Проверьте, пожалуйста, результат этапа [N]:

1. [Критерий 1] — Выполнено?
2. [Критерий 2] — Выполнено?
3. [Критерий 3] — Выполнено?
```

Спросить через AskUserQuestion:

```
questions: [
  {
    header: "Проверка",
    question: "Все критерии качества выполнены?",
    multiSelect: false,
    options: [
      { label: "Да, всё в порядке", description: "Этап принят" },
      { label: "Есть замечания", description: "Нужны доработки" }
    ]
  }
]
```

Если "Есть замечания" — попросить описать замечания.

## 5. Создать CHECK.md

Создать `.bpd/stages/NN-название/CHECK.md` по шаблону:
- Результаты автоматической проверки
- Результаты ручной проверки
- Итог: Принято / Доработать
- Замечания (если есть)

## 6. Обновить STATE.md

**Если принято:**
- Статус: "Проверен"
- Прогресс: пересчитать
- Последнее действие: "Этап N проверен и принят"
- Следующий шаг: `/bpd:plan` (следующий этап)

**Если доработать:**
- Статус: "Доработка"
- Последнее действие: "Этап N отправлен на доработку"
- Добавить замечания в раздел "Проблемы"
- Следующий шаг: `/bpd:do N`
