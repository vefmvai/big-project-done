Это самый важный момент — чем лучше поймём проект на старте, тем качественнее будут все этапы.
</purpose>

<process>

## 1. Проверка

Проверь существование папки `.bpd/` в текущей директории.

**Если `.bpd/` уже существует:**
Сообщи: "В этой папке уже есть проект BPD. Используй `/bpd:status` чтобы посмотреть прогресс."
Завершить.

**Если `.bpd/` нет:** Продолжить.

## 2. Интервью

**Открой разговор** (текстом, НЕ через AskUserQuestion):

"Расскажите, что за проект вы хотите сделать? Опишите в свободной форме — что это, для кого, какой результат хотите получить."

Дождись ответа.

**Задай уточняющие вопросы** (2-4 штуки, через AskUserQuestion или текстом — в зависимости от ситуации):

Обязательные темы:
- Какой конечный результат? (что получится в итоге — книга, курс, сайт, план...)
- Для кого это делается? (аудитория, заказчик, для себя)
- Есть ли ограничения? (сроки, бюджет, инструменты, объём)
- Есть ли опыт в подобных проектах?

Не нужно спрашивать все 4 вопроса, если ответы уже понятны из первого описания. Следуй за контекстом.

## 3. Выбор масштаба

Используй AskUserQuestion:

```
questions: [
  {
    header: "Масштаб",
    question: "Насколько масштабный проект?",
    multiSelect: false,
    options: [
      { label: "Быстрый (1-5 этапов)", description: "Небольшая задача на пару сессий" },
      { label: "Средний (5-15 этапов)", description: "Серьёзный проект на несколько дней" },
      { label: "Большой (15+ этапов)", description: "Масштабный проект на недели/месяцы" }
    ]
  }
]
```

## 4. Выбор режима

Используй AskUserQuestion:

```
questions: [
  {
    header: "Режим работы",
    question: "Как вы хотите работать?",
    multiSelect: false,
    options: [
      { label: "Интерактивный (рекомендуется)", description: "Claude спрашивает подтверждение перед каждым шагом" },
      { label: "Автоматический", description: "Claude делает сам, показывает результат в конце" }
    ]
  }
]
```

## 4.5. Сбор проектных фич

Проанализируй всё, что рассказал пользователь в ходе интервью. Если он упоминал специальные требования — зафиксируй их как проектные фичи.

Примеры фич:
- **Вести лог/черновик** по ходу проекта (для обучения, документации, отчёта)
- **Автосбор данных** — собирать метрики, статистику, ошибки
- **Параллельный артефакт** — создавать что-то параллельно с основной работой

Для каждой фичи проработай:
- Как она будет работать?
- Какие файлы создаются?
- Когда и как они обновляются?
- По какому принципу фильтруется информация?

Фичи будут записаны в config.json на шаге 5.

## 5. Создание config.json

Создай `.bpd/config.json`:

```json
{
  "project_name": "[название из интервью]",
  "scale": "[быстрый|средний|большой]",
  "mode": "[интерактивный|автоматический]",
  "use_subagents": [true если масштаб "большой", иначе false],
  "features": {[проектные фичи из шага 3.5, или пустой объект если фич нет]},
  "created": "[сегодняшняя дата]",
  "version": "1.1.0"
}
```

Пример features (если пользователь хочет вести образовательный лог):
```json
"features": {
  "edu_log": {
    "enabled": true,
    "file": ".bpd/EDU_LOG.md",
    "description": "Лог для образовательного материала",
    "filter": "Записывать только то, что поможет научить человека повторить результат"
  }
}
```

## 6. Создание PROJECT.md

Создай `.bpd/PROJECT.md` по шаблону. Заполни все поля из интервью.
Не сжимай информацию — запиши всё что узнал. Это главный документ проекта.

**PROJECT.md живёт дольше всех остальных файлов.** Он не перезаписывается,
а дописывается: по ходу проекта сюда добавляются принятые решения с обоснованием
(«что решили и почему»), а описание и рамки правятся, когда проект реально
поменялся. Файл, который стирают, — это `STATE.md`; сюда решения не писать.

## 7. Создание ROADMAP.md

Разбей проект на этапы. Количество зависит от масштаба:
- Быстрый: 1-5 этапов
- Средний: 5-15 этапов
- Большой: 15+

Для каждого этапа определи:
- Название (короткое, понятное)
- Описание (одно предложение)
- Цель (что этот этап даёт)
- Зависимости (от каких этапов зависит)
- Критерии готовности (2-5 пунктов)

Создай `.bpd/ROADMAP.md` по шаблону.

**Покажи дорожную карту пользователю.** Для интерактивного режима — спроси подтверждение:

```
questions: [
  {
    header: "Дорожная карта",
    question: "Вот дорожная карта проекта. Всё верно?",
    multiSelect: false,
    options: [
      { label: "Да, всё верно", description: "Сохранить и продолжить" },
      { label: "Нет, нужны изменения", description: "Хочу что-то поменять" }
    ]
  }
]
```

Если "Нет" — спроси что изменить, внеси правки, покажи снова. Повторяй до подтверждения.

## 8. Создание STATE.md

Создай `.bpd/STATE.md` по шаблону. Заполни:
- Название проекта и цель из PROJECT.md
- Текущий этап: 1 из N
- Статус: Не начат
- Прогресс: 0%
- Следующий шаг: `/bpd:plan`

## 9. Создание папок этапов

Для каждого этапа из ROADMAP.md создай пустую папку:
```bash
mkdir -p .bpd/stages/01-название
mkdir -p .bpd/stages/02-название
...
```

Имя папки: номер (с ведущим нулём) + дефис + название в нижнем регистре (транслит или латиница, без пробелов).

## 10. Создание/обновление CLAUDE.md

Создай или обнови `CLAUDE.md` в корне проекта по шаблону `templates/CLAUDE.md`.

Заполни все секции на основе информации из интервью и PROJECT.md:
- О проекте — краткое описание
- Технологии — все упомянутые технологии и инструменты
- Правила работы — специфичные для проекта (безопасность, конфиденциальность и т.д.)
- Память проекта — гибкие правила, исходящие из логики конкретного проекта
- Структура проекта — дерево директорий

**Важно:** правила памяти должны быть адаптированы под конкретный проект. Они должны помогать Claude в следующих сессиях понимать контекст и правильно работать с памятью.

## 11. Сохранение в project memory

Сохрани ключевую информацию о проекте и пользователе в project memory:

1. Определи путь к project memory (обычно `~/.claude/projects/<project-hash>/memory/`)
2. Создай файлы:
   - `user_context.md` — кто пользователь, его роль, контекст, уровень
   - `project_overview.md` — ключевые факты о проекте, инфраструктура, решения
   - `MEMORY.md` — индекс файлов памяти

Используй стандартный формат памяти с frontmatter (name, description, type).

## 12. Самопроверка

**Перед показом финальной сводки** пройди по success_criteria ниже.
Проверь каждый пункт. Если что-то не выполнено — **выполни сейчас**, не показывай сводку с незакрытыми пунктами.
