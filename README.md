# BPD — Big Project Done

Фреймворк для ведения больших проектов в Claude Code.

Вдохновлён [GSD (Get Shit Done)](https://github.com/gsd-build/get-shit-done), но адаптирован для **любых** задач, не только для кода. Написание книги, подготовка курса, исследование, организация мероприятия — любой проект, который не помещается в одну сессию.

## Что делает

- Разбивает большой проект на управляемые этапы
- Планирует каждый этап с конкретными задачами
- Выполняет задачи (для больших проектов — в свежем контексте через субагентов)
- Проверяет результат по чеклисту качества
- Хранит состояние в файлах — ничего не теряется между сессиями

## Установка

```bash
# В папке проекта:
bash /путь/к/big-project-done/install.sh
```

Скрипт копирует файлы в `.claude/` вашего проекта.

## Быстрый старт

```
/bpd:start    — расскажите Claude о проекте
/bpd:plan     — получите план первого этапа
/bpd:do       — выполните этап
/bpd:check    — проверьте результат
```

Повторяйте `plan → do → check` для каждого этапа.

## Все команды

| Команда | Что делает |
|---------|-----------|
| `/bpd:start` | Начать новый проект |
| `/bpd:plan [N]` | Спланировать этап |
| `/bpd:do [N]` | Выполнить этап |
| `/bpd:check [N]` | Проверить результат |
| `/bpd:status` | Показать прогресс |
| `/bpd:update` | Изменить дорожную карту |
| `/bpd:help` | Справка |

## Масштабы проектов

При старте вы выбираете масштаб:

| Масштаб | Этапов | Цикл работы |
|---------|--------|-------------|
| Быстрый | 1-5 | план → выполнение |
| Средний | 5-15 | план → выполнение → проверка |
| Большой | 15+ | план → выполнение (субагент) → проверка (субагент) |

## Структура файлов

После `/bpd:start` в проекте появляется папка `.bpd/`:

```
.bpd/
├── PROJECT.md     — описание проекта
├── ROADMAP.md     — дорожная карта
├── STATE.md       — текущее состояние
├── config.json    — настройки
└── stages/        — папки этапов
    ├── 01-название/
    │   ├── PLAN.md    — план этапа
    │   ├── RESULT.md  — результат
    │   └── CHECK.md   — отчёт проверки
    └── ...
```

## Ключевые принципы

1. **Борьба с context rot** — для больших проектов каждый этап выполняется субагентом в свежем контексте
2. **Сначала описание, потом действия** — спецификация → план → выполнение
3. **Атомарность** — маленькие конкретные задачи вместо "сделай всё"
4. **Всё в файлах** — состояние проекта сохраняется между сессиями
5. **Проверка результата** — чеклист качества для каждого этапа

## Советы

- Между этапами делайте `/clear` — свежий контекст работает лучше
- Дорожную карту можно менять в любой момент через `/bpd:update`
- Для быстрых проектов проверку можно пропускать
- Не удаляйте папку `.bpd/` — в ней вся память проекта
