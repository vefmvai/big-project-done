# BPD — Big Project Done

Ведение больших проектов в Claude Code. Проект режется на этапы; каждый этап
планируется, выполняется и проверяется. Состояние живёт в файлах, поэтому
переживает `/clear`, закрытый ноутбук и неделю простоя.

Подходит для любой работы, а не только для кода: книга, курс, исследование,
сайт, мероприятие.

## Команды

| Команда | Что делает |
|---|---|
| `/bpd:start` | Начать проект: интервью → дорожная карта → рабочие файлы |
| `/bpd:plan` | Спланировать следующий неспланированный этап |
| `/bpd:plan N` | Спланировать конкретный этап (или перепланировать) |
| `/bpd:do` | Выполнить следующий спланированный этап |
| `/bpd:do N` | Выполнить конкретный этап |
| `/bpd:check` | Проверить результат выполненного этапа |
| `/bpd:check N` | Проверить конкретный этап |
| `/bpd:status` | Показать прогресс: где мы и что дальше |
| `/bpd:update` | Изменить дорожную карту |
| `/bpd:help` | Эта справка |

## Рабочий цикл

```
/bpd:start
    │
    ├──► /bpd:plan ──► /bpd:do ──► /bpd:check ──┐
    │         ▲                        │        │
    │         └── «Доработать» ────────┘        │
    │                                            │
    └────────────── «Принято», следующий этап ◄──┘
```

Между этапами полезно делать `/clear` — прогресс хранится в файлах, а свежий
контекст работает заметно лучше замусоренного.

## Масштаб проекта

| Масштаб | Этапов | Как работает |
|---|---|---|
| Быстрый | 1–4 | план → выполнение, проверки нет |
| Средний | 5–14 | план → выполнение → проверка, всё в текущем чате |
| Большой | 15 и больше | то же, но планировщик, исполнитель и проверщик работают каждый в свежем контексте |

## Рабочая папка проекта

```
.bpd/
├── PROJECT.md   — что за проект, рамки, принятые решения (дописывается)
├── ROADMAP.md   — дорожная карта: этапы, цели, критерии готовности
├── STATE.md     — история, проблемы, следующий шаг (перезаписывается)
├── config.json  — настройки
└── stages/      — папки этапов: PLAN.md, RESULT.md, CHECK.md
```

**Не удаляйте `.bpd/`** — там вся память проекта.

Статус этапа нигде не хранится. Он вычисляется по тому, какие файлы лежат
в папке этапа: есть `PLAN.md` — спланирован, появился `RESULT.md` — выполнен,
в `CHECK.md` написано «Принято» — принят. Файлы создаёт сама работа, поэтому
соврать они не могут.

## Полезно знать

- Номера этапов не меняются никогда. После правок карты они могут идти
  вразнобой — это нормально, порядок задаёт дорожная карта, а не номер.
- Перепланировать этап можно в любой момент: `/bpd:plan N`.
- Отменённый этап уходит в раздел «Отменённые» карты, но его папка и файлы
  остаются на месте.
